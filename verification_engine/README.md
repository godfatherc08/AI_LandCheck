# Land Verification Engine

The `verification_engine` directory implements an explainable verification pipeline for Nigerian land documents. Its primary role is to transform a scanned certificate or related land record into a structured risk assessment by combining OCR, computer vision, field extraction, and deterministic rule checks. The implementation is intentionally modular so each layer can be inspected independently and tuned without retraining a single opaque model.

At runtime, processing starts in the OCR layer, where input PDF pages or images are normalized and read into text tokens, bounding boxes, and confidence values. This creates a machine-readable representation of the source document that can be consumed by later stages. In parallel with text extraction, the vision modules analyze scan artifacts and spatial inconsistencies that often indicate digital manipulation, such as copy-paste edits, compression anomalies, or unusual local noise patterns.

The extraction layer then maps noisy OCR text into domain fields such as reference numbers, ownership entities, dates, survey identifiers, local government area values, and land-use descriptors. Although this module is stored under `layoutLMV3`, the current implementation is pattern-driven and optimized for practical field recovery on the document formats already seen in this codebase. This design favors operational reliability and straightforward debugging over model complexity.

After field recovery, the rules and agent modules evaluate internal consistency and contextual plausibility. They check whether date relationships are logically possible, whether numbering formats match expected governmental conventions, whether location and state references align, and whether key authenticity indicators are missing or contradictory. The agent layer orchestrates these tools into a weighted interpretation so the final output is not just raw extraction data but a decision-oriented summary with explicit reasons.

The architectural function of the directory is therefore twofold: first, to standardize unstructured land-document evidence into structured signals; second, to translate those signals into a risk narrative that can support due diligence, legal review, lending checks, or fraud triage. The implementation reflects an engineering tradeoff toward transparency and extensibility, where each stage can be validated independently and improved incrementally as more document variants are observed in production.

Operationally, the OCR entry script writes outputs to `OCR/verification_results`, including machine-readable artifacts and verification summaries that preserve traceability to source pages. This output strategy makes the system suitable for iterative threshold tuning, audit workflows, and downstream automation where confidence, provenance, and explanation quality matter as much as raw detection performance.
